feat(storage): 混合存储 hybrid 与 Redis 历史回收（收口）

在混合存储骨架之上补齐以下关键项：

redis:
- CLEAR_UNDO_LUA 原先只 DEL 索引集合，undo 实体 hash 从此再无人引用；
  现在先 SMEMBERS 再逐个 DEL，避免"写了就成孤儿、恢复扫描也扫不到"的内存泄漏
- 兜底 TTL 落到 create/transition/save/updateRecovery 每次写入时刷新，
  活跃事务永不到期，只有清理器也挂了的孤儿键才由 Redis 回收
- RedisCleanup 对未到期候选重新打分为 now 排到队尾，避免占满批次导致清理停滞

core:
- AtTransactionManager 统一 undo/簿记出口 persist(tx)：undo 走 UndoRepository、
  簿记走 updateRecovery；required(xid) 在显式注入时合并两侧存储
- CleanupScheduler 级联钩子用 Consumer<List<String>> 承接被删 xid

boot2/boot3:
- Java 8 编译目标下 Duration.toSeconds() 不可用，改用 getSeconds()

sql: db/{mysql,postgresql}/undo-only.sql（混合模式只需这一张 undo 表）
test: HybridUndoStorageTest 5 例（含反向验证：非连接绑定存储业务回滚后 undo 残留）
      RedisCleanupIT 3 例（真实 Redis：终态完整删除、重写不泄漏、ACTIVE 不清理且带 TTL）
docs: README「混合存储」「Redis 历史清理」、USAGE、PRODUCTION_GAPS §19、RUNBOOK §5.1/§5.2

验证：mvn -o clean verify 87 全绿；-Pdbtest 真实库 15/15
