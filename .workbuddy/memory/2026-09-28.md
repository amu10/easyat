## easy-at-example-boot3 新增远程事务（OpenFeign + Nacos）示例
- 用户要求：在 easy-at-example-boot3 内生成 OpenFeign 跨服务远程事务例子，Nacos=192.168.110.237:8848，用该例子自己的数据库（easyat01），要能自调，覆盖"事务成功"与"事务失败回滚"两种场景。
- 设计：单模块内用两个 Spring Profile 跑出两个进程（caller=order-service:18081 / callee=inventory-service:18082），共用 easyat01 库（共享 easy_at_* 协调表）。caller 用 `@EasyAtTransactional` 起全局事务→扣 account+写 orders→Feign 调 callee 扣 inventory；callee 经 `AtXidFilter.join(xid)` 加入同一事务。
- 关键机制（已读源码确认）：`EasyAtFeignInterceptor`(Feign RequestInterceptor, feign 在 classpath 时自动注册) 把 AtContext.xid() 注入请求头；`AtXidFilter` 收到后 `manager.join(xid)`→`AtContext.bind`；callee 的 `@EasyAtTransactional` 见 AtContext.active() 即跳过 begin。`JdbcAtRepository.create` 用自己的连接 auto-commit 立即提交 XID，故 callee 的 join 必能查到；caller 回滚时 `find(xid)` 的 `loadUndo` 会加载该 XID 下全部 undo（含 callee 写入共享 easy_at_undo_log 的），逆序补偿 → 跨服务回滚成立。
- 改动文件：pom.xml（加 spring-cloud-dependencies 2023.0.3 / spring-cloud-alibaba-dependencies 2023.0.3.2 BOM + openfeign/nacos-discovery/loadbalancer 依赖）；application.yml 拆出 application-caller.yml/application-callee.yml；schema.sql 加 orders/inventory 表+库存种子；新增 remote/dto.DeductResult、remote/caller.{InventoryFeignClient,CallerConfig,OrderService,OrderController}、remote/callee.{InventoryService,InventoryController}；README 新增远程事务章节。
- 注意：callee 的 InventoryService 故意**不加** `@EasyAtTransactional`（只 `@Transactional`），靠过滤器 join 全局；caller 加。两服务必须连同一 easyat01（join 会查库找 XID，分离库会报 Transaction not found）。Nacos discovery 仅在 profile 内开启，避免无 profile 的本地转账 demo 去连 Nacos。
- 版本兼容：Spring Boot 3.3.3；若依赖解析失败按本地版本调 pom 里 spring-cloud-alibaba.version。
- 运行：easyAt 根 `mvn install -DskipTests` → 进 example 目录两终端分别 `mvn spring-boot:run -Dspring-boot.run.profiles=caller/callee`；成功 `POST /order?userId=1&itemId=1001&qty=2`，失败加 `&fail=true` 或 qty 超库存；观测 `GET /order/state`、`/demo/transactions`、`/demo/undo-logs`。

## 远程示例启动/运行期两个错误修复（同一天再次调整）
- 用户贴 callee 启动失败日志，两个独立根因：
  1. `NacosException: Client not connected, current status:STARTING`，且 `NacosDiscoveryProperties` 打印 `serverAddr='null'`。
     根因：yml 把地址写在 `spring.cloud.nacos.server-addr`，而 `NacosDiscoveryProperties` 绑定前缀是
     `spring.cloud.nacos.discovery`，只认 `spring.cloud.nacos.discovery.server-addr`（顶层那个是给 config 客户端的
     NacosCommonProperties 用的，discovery 不读）。坑：日志里 `username='******'` 是 toString **恒定掩码**，
     不能当作"用户名已生效"的证据——真正暴露问题的是 `serverAddr='null'`。
     修复：caller/callee 的 `spring.cloud.nacos.discovery` 下补齐 server-addr/username/password。
  2. `NoClassDefFoundError: com.fasterxml.jackson.core.exc.StreamConstraintsException`（后台预加载线程，非致命但说明版本错）。
     该类自 jackson-core **2.15.0** 才有，nacos-client 2.4.x 的 `JacksonUtils` 需要它。根因：示例 pom 从未导入
     `spring-boot-dependencies` BOM，jackson 无人管理被解析成 <2.15 旧版。
     修复：BOM 集中到聚合 pom（spring-cloud / spring-cloud-alibaba / **spring-boot-dependencies 放最后**），
     并在 caller/callee 显式声明 `jackson-core`/`jackson-databind` = `${jackson.version}`(2.17.2)；删掉子模块各自的 dependencyManagement。
- 运行期再报 `UnsupportedAtSqlException`：见 MEMORY.md「AT 模式受限 SQL」。改 caller/callee 三处 SQL 为
  「先读旧值→Java 算新值→整体写入」。
- README 端口与 yml 不一致（README 18081/18082，yml 实为 18181/18182，日志确认 18182）→ 按 yml 实际值统一改 README。
- 已校验：3 个示例 pom XML 均 well-formed（python minidom 解析通过）。

## 增加 XID 跨服务传播观测点（同一天再次调整）
- 用户问"怎么才能看 xid 有没有通过 openfeign 传过去"。机制确认（已读源码）：
  caller `EasyAtFeignInterceptor`（easy-at-spring，Feign `RequestInterceptor`）在 `AtContext.xid()!=null` 时写
  `X-EasyAt-Xid` / `X-EasyAt-Deadline`(now+30s) / `X-EasyAt-Source`(appName) / `X-EasyAt-Signature`(仅 signer.isConfigured())；
  callee `AtXidFilter`（boot3-starter）读 `X-EasyAt-Xid`，且 `!AtContext.active()` 时 `manager.join(xid)`，finally `AtContext.clear()`。
  头名常量统一在 `io.github.easyat.core.AtTransportHeaders`。
- 新增观测点：caller `OrderService` 打 `[AT-caller] 全局事务已开启/将传出 xid=`；
  callee `InventoryService` 打 `[AT-callee] joined xid= (inAT=)`；
  caller application.yml 开 `spring.cloud.openfeign.client.config.default.loggerLevel=FULL` +
  `logging.level.io.github.easyat.example.caller.InventoryFeignClient: DEBUG`（FULL+DEBUG 才会打印请求头）。
- caller `OrderController#state` 增加 `undoLogs`（查 easy_at_undo_log；同 xid 下 caller(account/orders) 与 callee(inventory)
  各有一条 = 传播+join 成功，这是最硬的端到端证据）。
- 路径坑（README 已修）：`OrderController` 实际是 `POST /order/place`（README 原写 `/order`）；
  `/demo/accounts|transactions|undo-logs` 只在 local(18080)，caller 上没有（caller 只有 /order/place、/order/state）。
- 用户自行把 caller/callee 的 `spring.cloud.nacos.discovery.server-addr/username/password` 注释掉并加了 `ip: 127.0.0.1`；
  已保留其改动，仅加注释提示（若再报 Client not connected/STARTING 就放开那三行）。
