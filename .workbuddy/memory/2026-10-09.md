## easyAt 0.1.1 生产可行性评估（结论：不建议上核心生产）

用户问「这个版本能用在生产环境吗」，基于实测证据给出结论。

### 关键事实（评估依据）

- **测试规模**：33 个用例全绿（jdbc 31 + boot2 1 + boot3 1），**全部跑在 H2 内存库**。
  13 个测试类，无任何 Testcontainers → MySQL / PostgreSQL / Redis 真实实例从未验证过。
- **0.1.1 并非只改版本号**，0.1.0（09-28 发布）之后核心一致性逻辑连改三次：
  - 09-29 `b60c51f` 重写 `SqlUndoLogGenerator`(-198 行) + `AtDataSource`(+170 行)，加 batch/多行 IN
  - 09-30 `7b9ff52` 批量最多 100 行主键 IN
  - 10-08 `fdaac96` 修 `JdbcGlobalLockManager`(42 行) + `AtTransactionManager` 回滚重试
    → **回滚重试与锁过期接管改完当天就发布了 0.1.1**，无 soak time
- **PRODUCTION_GAPS.md 第 9 节**列出的 9 类测试（真实库 Testcontainers、多实例并发恢复、
  锁竞争续租、写 undo/DML/提交前后故障注入、网络超时重启、脏写幂等）**一项都没做**。
- SQL 边界见 `SQL_COMPATIBILITY.md`：`NOW()`/`CURRENT_TIMESTAMP` 在 Generic 不支持、
  MySQL/PG 才支持 → 这些方言分支从未在真库跑过。跨列计算、非白名单函数仍拒绝。

### 给出的建议

- 可用：内部工具 / 后台任务 / 非资金数据 / 单实例低并发 / 有对账与人工修复手段。
- 不可用：资金、订单、库存、账务，或多实例高并发强一致场景。
- 上线前最小验证清单：① jdbc 31 用例改跑 MySQL 8 Testcontainers；② 7 个故障注入点；
  ③ 多实例锁竞争 + 长事务续租 + 崩溃接管；④ Redis 路径集成测试（现仅 1 个自动配置冒烟用例）；
  ⑤ 影子运行对账 `easy_at_global` / `easy_at_undo_log` 后再灰度。

### 修复清单（全部完成）

| # | 缺陷 | 修复要点 |
|---|---|---|
| 1 | 空回滚缺失（`act()` 对未知分支 `orElseThrow`） | `BranchCoordinator#emptyRollback` 落 `ROLLED_BACK` 占位记录；rollback 幂等成功 |
| 2 | 防悬挂缺失（注册不看 status、`join` 不校验状态） | `DefaultBranchRegistrar`/`BranchCoordinator#register` 拒绝已回滚资源；`AtTransactionManager#join` 只接受 ACTIVE（`AtStatus#isJoinable`）；`append` 写 undo 前二次校验 |

| 5 | 失败态被洗白（ROLLBACK_FAILED 可被 commit 置 COMMITTED） | `actExisting` 阻止非法前驱提升为 `COMMITTED` |
| 6 | 投递重试无上限 / finally 抹掉人工介入 | `BranchRetryScheduler` 接入 maxRetries + metrics，耗尽转 `MANUAL_INTERVENTION`；`AtRecoveryScheduler#finally` 跳过人工态；`drive` 逆序 + 单分支异常隔离 |

### 真实库当场暴露的 4 个缺陷（3 修 1 存疑）

| # | 缺陷 | 状态 |
|---|---|---|
| 1 | **PG 回滚 100% 失败**：`pk_value` 是 VARCHAR 列 → 读回永远是 String → `setObject` 让 PG 驱动发成 varchar → `bigint = character varying` | ✅ 修：`JdbcUndoExecutor` 新增 `bind()`（按 Java 类型选 setter）+ `coerce()`（查列元数据把 String 还原为列类型，`表.列` 缓存） |
| 2 | **Redis 加锁 Lua**：`tonumber(lease)` 是 number，`now` 取 ARGV 是 string → `attempt to compare number with string`，`eval` 抛异常 | ✅ 修：`now=tonumber(ARGV[3])` + `lease~=nil` 保护 |
| 3 | **jedis 二进制不兼容**：按 jedis 3.8.0 编译，classpath 上 4.x/5.x（Spring Boot 3 默认 5.x）时 `NoSuchMethodError: Jedis.hset(String,Map)` | ⚠️ 未修（需升级 API，涉及依赖契约变更）；db-tests 锁定 3.8.0 避免掩盖 |
| 4 | **并发回滚重复补偿 → 假性 DIRTY_WRITE**：`rollback` 里 `status != ROLLING_BACK && !transition(...)` 在状态已是 ROLLING_BACK 时**短路跳过 CAS**，两个执行者并发跑同一条 undo，后到的脏写校验误判 | ✅ 修：`AtTransactionManager` 新增 `enterRollback`/`exitRollback`——单 JVM 用 `rollbackInFlight` 集合，跨实例用租约（同 owner 可重入以兼容 `AtRecoveryScheduler`，过期允许接管）；owner 经由新增构造器注入，boot2/boot3 装配传入 |

## 16:40-16:55 分支状态原子性（§4.3）收口 + 版本 0.1.2

- 最后一项技术阻断：分支注册走框架独立连接，业务本地事务回滚后分支行残留（协调器会去回调一个
  什么都没做的资源，既不收敛也不告警）。
- 修法：`BranchRepository#registerIn(AtBranch, Object localConnection)`（参数用 Object 保持 core
  存储无关）+ `BranchRegistrar#register(xid, resourceId, Object conn)` 三参数默认方法（两参数版委托
  传 null，既有实现二进制兼容）；`SqlUndoLogGenerator#capture` 把业务**物理**连接 `c` 传下去
  （`target.getConnection()`，不经代理故不会递归注册）。
- **两个必须处理的坑**：① 同事务多条 DML 都会走到注册 → 在业务连接上查重（能看见本事务未提交的
  行）；② 仍撞唯一键冲突 → 回滚到 savepoint，否则 **PostgreSQL 一句报错会把整个业务事务打成
  aborted**，后续语句全失败。
- 回归 `BranchRegistrationAtomicityTest` 4 例（H2，分支表带 UNIQUE），含**反向验证**（关掉
  registerIn 后业务回滚确实残留分支）——证明不是假绿。
- 版本 0.1.1 → 0.1.2（13 个 pom：version/parent/scm.tag/deploymentName）。提交 `5368be5`。
- 验证：默认 `mvn clean verify` 12 模块 **69 用例**全绿；`-Pdbtest` 真实 MySQL5.7/PG16/Redis7 **9/9**。

## 17:10-17:45 通用快照路径：子查询 / JOIN / 多行 INSERT

用户要求「需要支持 批量/JOIN/子查询 而不是直接抛 UnsupportedAtSqlException」。

核心思路：不再要求框架理解 WHERE，而是**把原语句的 FROM/WHERE/ORDER BY/LIMIT 拼成一条 SELECT
先读出所有受影响行**（`SELECT <alias>.* FROM ... WHERE <原 where>`），再逐行建 undo + 逐行加锁。
- UPDATE undo = 整行（除 PK）改回 before image；DELETE undo = 整行插回。
- 整行还原而非「只还原变化的列」：通用路径不解析 SET 表达式（可能是子查询/函数/跨列运算），
  无法在编译期知道哪些列会被改。

新增：`GenericSnapshotPlanner` / `GenericAtExecutor`；`SqlUndoLogGenerator#capture` 严格路径抛
UnsupportedAtSqlException 后回退。

### JSqlParser 4.9 解析要点（踩过的坑）
- `UPDATE a JOIN b ON ...` → JOIN 在 `getStartJoins()`，元素是 `Join`
- `UPDATE a, b SET ...` → 第二个表也在 `startJoins`，但**渲染不带 JOIN 关键字**，拼 FROM 必须补逗号，
  否则得到 `FROM a b` 语法错误
- PG `UPDATE ... FROM` → 在 `getFromItem()`
- `DELETE a FROM a JOIN b ...` → `getJoins()` + `getTables()=[a]`
- `Table.getAlias()` 返回 **`Alias` 对象**不是 String，要 `.getName()`
- **`Insert.getValues()` 对 `INSERT...SELECT` 抛 ClassCastException**，要先判断 `getSelect() instanceof Values`
- 多行 VALUES：`Values.getExpressions()` 元素是 `ParenthesedExpressionList`（extends ExpressionList）；
  单行时元素直接是 Expression

### 最大的坑：参数计数
`ExpressionVisitorAdapter` **不下钻 SubSelect**，会把 `WHERE id IN (SELECT ... WHERE x=?)` 的 `?`
漏掉 → 参数绑定错位。必须用 `net.sf.jsqlparser.util.deparser.ExpressionDeParser` + `SelectDeParser`
（还顺带正确处理字符串字面量里的 `?`）。

### 别名 / WHERE 非主键
`RecognizerSupport#tableName` 对别名、以及 `assertPrimaryKey` 对「WHERE 不是主键」，原本抛
`AtException` → 改成抛 `UnsupportedAtSqlException`，才能触发回退到通用路径。

### 仍拒绝（正确性边界）
多目标表 DML（`UPDATE a,b SET a.x=?,b.y=?`）、`SET pk=?`、无主键/复合主键表、`INSERT ... SELECT`、
依赖自增主键却不写主键列、DDL/TRUNCATE/MERGE/存储过程。

### 验证
`mvn clean verify` 12 模块 **72 用例**全绿；`-Pdbtest` 真实库 **12/12**（新增 JoinAndSubqueryAtIT 3 例：
MySQL 5.7 `UPDATE ... JOIN`、MySQL 子查询 DELETE、PG `UPDATE ... FROM`）。
注意：db-tests 建表要按方言分开——MySQL 用 DATETIME+BLOB（5.7 严格模式下 TIMESTAMP 无默认值会报
"Invalid default value"），PG 用 TIMESTAMP+BYTEA。

## 20:29 Redis 存储风险评估（用户问 undo 全存 Redis 会不会不回收）

**答：会。而且"不回收"是最轻的那个问题。** 结论写进 `PRODUCTION_GAPS.md` §18.4。

### 三个问题（按严重度倒序）

1. **undo 不再与业务 DML 原子提交（P0，选型级）**
   `AtTransactionManager#append(Connection, UndoRecord)` 只在 `repository instanceof
   ConnectionBoundAtRepository` 时走业务连接；**全仓只有 `JdbcAtRepository` 实现了它**，
   `RedisAtRepository` 只 `implements AtRepository` → 落到 `tx.addUndo + repository.save(tx)`，
   **立刻独立写 Redis，不在业务本地事务里**。与 PRODUCTION_GAPS §2.3「本地事务强制保障」直接冲突：
   业务回滚而 undo 已落 Redis / Redis 写失败而业务已提交 → 无法回滚。加清理任务也救不了这个。

2. **键只增不减（P0）**
   `easy-at:global:<xid>`、`easy-at:global:status:<终态>` 集合成员、`easy-at:undo:<xid>:<uuid>`、
   `easy-at:branch:<id>` / `branch:uniq:` —— **全部没有删除路径**。
   `save()` 里 `CLEAR_UNDO_LUA` 的 KEYS[1] 只是**索引集合** `easy-at:undo:<xid>`，
   实体 hash `easy-at:undo:<xid>:<uuid>` 写过就成孤儿，`recoverable()` 扫不到。
   **只有锁会回收**：`RedisGlobalLockManager#releaseByXid` → `RELEASE_LUA` DEL 锁 key 与 byXid 集合。

3. **量级**：单条 undo 存整行 before **+** after image，JSON 后 base64(×1.33) → 20 列的行约 **3–8 KB/条**。
   日均 100 万事务 × 3 DML ≈ 300 万条 × 5 KB ≈ **15 GB/天**。撞 maxmemory 后若配了 `allkeys-lru`，
   被淘汰的可能正是未收敛事务的 undo → **静默无法回滚**。
   另：`save(tx)` 是全量重写该事务所有 undo，每条 DML 触发一次 → **O(N²)** 次 HSET + 往返。

### 结论

生产用 **JDBC 存储**（undo 必须和业务 DML 同连接同事务，这是 AT 正确性前提，不是惯例）。
Redis 存储只适合验证/演示。真要继续用 Redis 需补三件事（仍不解决问题 1）：zset 终态索引清理、
undo TTL + 活跃事务续期、与 §2.3 对齐的持久化确认。

## 20:40-21:10 实现混合存储（hybrid）+ Redis 回收

用户拍板：「需要支持 混合方案，还有就是 单独 redis storage 的形式」。两项都已实现，全部验证通过。

### 架构改动：undo 存储从 AtRepository 里拆出来

新增 SPI（core）：
- `UndoRepository`：`load(xid)` / `replaceAll(xid, records)` / `deleteByXid(xid)`
- `ConnectionBoundUndoRepository extends UndoRepository`：`append(Connection,…)` / `updateUndo` / `removeUndo`
- `CleanupScheduler`：与存储无关的清理调度，`Task` 返回被删 xid，交给 `Consumer<List<String>>` 做级联

`JdbcAtRepository` 现在 `implements ConnectionBoundAtRepository, ConnectionBoundUndoRepository`
（三个方法签名本来就一致，只需补 load/replaceAll/deleteByXid；把 `loadUndo` 抽成 `readUndo(c,xid)` 复用）。
新增 `JdbcUndoRepository`（只依赖 `easy_at_undo_log`，混合模式专用）。
`AtTransactionManager` 新增 7 参构造器（旧构造器全部委托，二进制兼容），统一出口 `persist(tx)`：
undo 走 `UndoRepository`、簿记走 `updateRecovery`；`required(xid)` 在显式注入时把两侧拼起来。

**关键设计判断**：不给 `RedisAtRepository` 实现 `ConnectionBoundUndoRepository`——Redis 连接无法参与
JDBC 本地事务的提交/回滚，"原子"是做不出来的。用 `storage.type` 显式区分，避免使用者误以为两者等价。

### Redis 回收

- `RedisCleanup`：`easy-at:cleanup:index` zset（member=xid、score=updated_at）按时间捞候选，
  单条 Lua 删 global hash + undo 索引 + 所有 undo 实体 + branch 实体/uniq/status 成员 + 残留锁 + ZREM。
- **未到期候选会 ZADD 成 now 排到队尾**——否则 ACTIVE 卡住的事务占满 batch 会让清理完全停滞；
  长期静止后 score 自然老化回队首重新参与扫描，不会漏。
- 兜底 TTL：`RedisAtRepository` 在 create/transition/save/updateRecovery 每次写入时刷新 EXPIRE
  （`easy-at.redis.ttl` 默认 30d），活跃事务永不到期。
- **孤儿键修复**：`CLEAR_UNDO_LUA` 原先只 DEL 索引集合，实体 hash 写完就成孤儿；现在先 SMEMBERS 逐个 DEL。

### 装配

boot2/boot3：`EasyAtRedisAutoConfiguration` 的条件从 `havingValue="redis"` 改成
`@ConditionalOnExpression("'${easy-at.storage.type:file}' == 'redis' || ... == 'hybrid'")`；
