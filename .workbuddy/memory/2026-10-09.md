## easyAt 0.1.1 生产可行性评估（结论：不建议上核心生产）

用户问「这个版本能用在生产环境吗」，基于实测证据给出结论。

### 关键事实（评估依据）

- **测试规模**：33 个用例全绿（jdbc 31 + boot2 1 + boot3 1），**全部跑在 H2 内存库**。
  13 个测试类，无任何 Testcontainers → MySQL / PostgreSQL / Redis 真实实例从未验证过。
- **0.1.1 并非只改版本号**，0.1.0（09-28 发布）之后核心一致性逻辑连改三次：
  - 09-29 `b60c51f` 重写 `SqlUndoLogGenerator`(-198 行) + `AtDataSource`(+170 行)，加 batch/多行 IN
  - 09-30 `7b9ff52` 批量最多 100 行主键 IN
  - 10-08 `fdaac96` 修 `JdbcGlobalLockManager`(42 行) + `AtTransactionManager` 回滚重试
    → **回滚重试与锁过期接管改完当天就发布了 0.1.1**，无 soak time
- **PRODUCTION_GAPS.md 第 9 节**列出的 9 类测试（真实库 Testcontainers、多实例并发恢复、
  锁竞争续租、写 undo/DML/提交前后故障注入、网络超时重启、脏写幂等）**一项都没做**。
- SQL 边界见 `SQL_COMPATIBILITY.md`：`NOW()`/`CURRENT_TIMESTAMP` 在 Generic 不支持、
  MySQL/PG 才支持 → 这些方言分支从未在真库跑过。跨列计算、非白名单函数仍拒绝。

### 给出的建议

- 可用：内部工具 / 后台任务 / 非资金数据 / 单实例低并发 / 有对账与人工修复手段。
- 不可用：资金、订单、库存、账务，或多实例高并发强一致场景。
- 上线前最小验证清单：① jdbc 31 用例改跑 MySQL 8 Testcontainers；② 7 个故障注入点；
  ③ 多实例锁竞争 + 长事务续租 + 崩溃接管；④ Redis 路径集成测试（现仅 1 个自动配置冒烟用例）；
  ⑤ 影子运行对账 `easy_at_global` / `easy_at_undo_log` 后再灰度。

### 状态

- 0.1.1 bundle 仍在 Portal 待 Publish（deploymentId `373fa6ed-21b2-4940-8316-fb1ac7326b94`）。
  用户可据此决定是先自测再公开，还是先 Publish 后在非关键服务试跑。

## 用户决定「开始修影响生产的功能」——已修 6 项

### 修复清单（全部完成）

| # | 缺陷 | 修复要点 |
|---|---|---|
| 1 | 空回滚缺失（`act()` 对未知分支 `orElseThrow`） | `BranchCoordinator#emptyRollback` 落 `ROLLED_BACK` 占位记录；rollback 幂等成功 |
| 2 | 防悬挂缺失（注册不看 status、`join` 不校验状态） | `DefaultBranchRegistrar`/`BranchCoordinator#register` 拒绝已回滚资源；`AtTransactionManager#join` 只接受 ACTIVE（`AtStatus#isJoinable`）；`append` 写 undo 前二次校验 |
| 3 | COMMITTING 黑洞（不在 recoverable 集合 + 无法转人工介入） | `AtStatus` 放行 `COMMITTING→MANUAL_INTERVENTION`；新增 `AtTransactionManager#finishCommit`；三个 `AtRepository#recoverable` 纳入 COMMITTING；`AtRecoveryScheduler` 按状态分派 |
| 4 | 分支状态非 CAS（`save()` 无条件覆盖，状态机是死代码） | `BranchCoordinator#advance` 全改用 `transition` CAS；`BranchStatus` 迁移表补齐并新增 `MANUAL_INTERVENTION` |
| 5 | 失败态被洗白（ROLLBACK_FAILED 可被 commit 置 COMMITTED） | `actExisting` 阻止非法前驱提升为 `COMMITTED` |
| 6 | 投递重试无上限 / finally 抹掉人工介入 | `BranchRetryScheduler` 接入 maxRetries + metrics，耗尽转 `MANUAL_INTERVENTION`；`AtRecoveryScheduler#finally` 跳过人工态；`drive` 逆序 + 单分支异常隔离 |

顺带修：`CoordinationService` 返回真实 HTTP 码（401/400/409）——此前错误用 200 返回会被
`deliverRemote` 判成回滚成功；新增 `BranchRepository#findByXidResource`（default 方法，三存储无需改动）。

### 真实库当场暴露的 4 个缺陷（3 修 1 存疑）

| # | 缺陷 | 状态 |
|---|---|---|
| 1 | **PG 回滚 100% 失败**：`pk_value` 是 VARCHAR 列 → 读回永远是 String → `setObject` 让 PG 驱动发成 varchar → `bigint = character varying` | ✅ 修：`JdbcUndoExecutor` 新增 `bind()`（按 Java 类型选 setter）+ `coerce()`（查列元数据把 String 还原为列类型，`表.列` 缓存） |
| 2 | **Redis 加锁 Lua**：`tonumber(lease)` 是 number，`now` 取 ARGV 是 string → `attempt to compare number with string`，`eval` 抛异常 | ✅ 修：`now=tonumber(ARGV[3])` + `lease~=nil` 保护 |
| 3 | **jedis 二进制不兼容**：按 jedis 3.8.0 编译，classpath 上 4.x/5.x（Spring Boot 3 默认 5.x）时 `NoSuchMethodError: Jedis.hset(String,Map)` | ⚠️ 未修（需升级 API，涉及依赖契约变更）；db-tests 锁定 3.8.0 避免掩盖 |
| 4 | **并发回滚重复补偿 → 假性 DIRTY_WRITE**：`rollback` 里 `status != ROLLING_BACK && !transition(...)` 在状态已是 ROLLING_BACK 时**短路跳过 CAS**，两个执行者并发跑同一条 undo，后到的脏写校验误判 | ✅ 修：`AtTransactionManager` 新增 `enterRollback`/`exitRollback`——单 JVM 用 `rollbackInFlight` 集合，跨实例用租约（同 owner 可重入以兼容 `AtRecoveryScheduler`，过期允许接管）；owner 经由新增构造器注入，boot2/boot3 装配传入 |

### 两个易踩的坑（本次亲历）

1. **surefire 默认只匹配 `*Test.java`**：`*IT.java` 会被静默跳过并显示 BUILD SUCCESS（"什么都不跑"的假绿）。
   已在 db-tests pom 显式配置 `<includes>`。
2. **孤儿锁会被合法抢占**：`JdbcGlobalLockManager` 对 `easy_at_global` 中不存在的 XID 视为孤儿事务，
   允许抢占。写锁互斥测试时必须先创建真实 ACTIVE 事务行，否则断言永远失败（我踩了两次）。

### 验证结果

- 默认 `mvn clean verify`：12 模块 BUILD SUCCESS，**59 用例全绿**（49 jdbc + 8 spring + 2 starter）。
- `mvn -Pdbtest test`：13 模块 SUCCESS，真实库 **9/9 全绿**（MySQL 3、PG 3、Redis 3）。
- 反向验证：临时禁用新加的回滚互斥后，并发用例立即报
  `DirtyWriteException: Dirty write detected for account/1` —— 证明测试确有捕获能力，不是假绿。

## 改用用户本机 MySQL 5.7 + 本地 Redis 跑真实验证（9/9 绿）

用户提供了本机账号：MySQL `127.0.0.1:3306`（root/root，库 `test_sport`）、
Redis `127.0.0.1:6379`（口令 `Redis,./`）。

### 环境实测

- 3306 实际是 **MySQL 5.7.44**（`mysql_native_password`），3306/6379 都由 `wslrelay` +
  `com.docker.backend` 中继 → 用户本机 MySQL/Redis 大概率跑在 WSL2 里。
- 6379 未认证时返回 `-NOAUTH Authentication required`；`AUTH Redis,./` → `+OK`，`PING` → `+PONG`。
- `test_sport` 是**真实业务库**（ggsport 全套表，`app_*`/`activity_*` 等上百张）→ 绝不能把 IT 指过去。

### 为安全做的两处改动（db-tests 测试代码）

1. `RealDatabaseSupport.RedisTarget` 新增 `database()`；外部实例读
   `easyat.it.redis.database` / `EASYAT_IT_REDIS_DATABASE`（默认 0）。
   `RedisRealStorageIT#pool` 改为 `new JedisPool(config, host, port, 5000, password, database)`。
   **原因**：用例会 `FLUSHDB`，指共享 Redis 时必须靠 db 隔离（本轮用 db 5）。
2. MySQL 侧新建专用空库 `easy_at_it`（utf8mb4），IT 指 `jdbc:mysql://127.0.0.1:3306/easy_at_it`。
   **原因**：`MysqlRealDatabaseIT` 的 SCHEMA 里有 `DROP TABLE IF EXISTS t_account / easy_at_*`。
3. 顺手给 redis 口令加了环境变量读取（`EASYAT_IT_REDIS_PASSWORD`），原先只有系统属性。
4. `easy-at-db-tests/README.md` 补「指向共享实例前的两条硬性要求」+ 本机示例命令。

### 结果

`mvn -o -Pdbtest -pl easy-at-db-tests -am test` + 上述属性 → **9/9 全绿**（约 19s）：
MySQL **5.7** 3/3、PG 3/3（本机无 PG，走 Testcontainers）、Redis（带 AUTH、db 5）3/3。

> 注：这是首次在 **MySQL 5.7**（而非容器里的 8.0）上验证，且是首次用**带密码的 Redis** 验证。
> jedis 3.8.0 客户端对本地 Redis 正常工作（兼容性问题只出在 classpath 混入 jedis 4/5 时）。

## 用户拍板「把投产三项实现了」——全部完成

### ① jedis 版本兼容（真因不是版本号，是返回值类型）

- 关键发现：jedis **写**命令返回类型在 4.x 起从 `Long`/`Boolean` 改成 `long`/`boolean`，
  而 JVM 方法描述符含返回类型。**Boot 2.7 BOM 管 jedis 3.8.0、Boot 3.5 BOM 管 jedis 6.0.0**，
  运行期版本由使用者的 dependencyManagement 决定，我们改声明版本没用。
- 修法：`easy-at-storage-redis` 三个类改为**只调用跨 3.8→6.0 签名稳定的 API**——
  写操作全走 `eval(String, List<String>, List<String>)`（HSET/SADD/DEL/SETNX 写进 Lua），
  读只用 `hget/hgetAll/smembers/get`。编译版本升到 **4.4.6**。
- 验证：db-tests 加 `-Pjedis3/-Pjedis5/-Pjedis6` profile，本地真实 Redis 上
  **3.8.0 / 4.4.6 / 5.2.0 / 6.0.0 四档各 3/3 全绿**。
- 环境坑：Nexus 是 http，Maven 3.9 的 `maven-default-http-blocker` 拦掉了
  → `mvn dependency:get` 不通，改用 `curl http://192.168.110.237:8181/...` + `install:install-file`。
  装完还要删掉 `_remote.repositories`，否则离线 `-o` 因 repo id 不匹配仍拒绝解析。

### ② (xid, resource_id) 唯一约束

建表脚本加 UNIQUE、新增 `db/{mysql,postgresql}/migration/v0.1.2__branch_unique.sql`（先去重再约束）；
`JdbcBranchRepository#register` 幂等（先查 + SQLState 23xxx/1062 兜底并发窗口）并 override
`findByXidResource` 走索引；`RedisBranchRepository` 用 `branch:uniq:` 键 SETNX 抢占；
`FileBranchRepository` 写锁内扫重。回归：`ReconciliationTest#detectsDuplicateBranchRegistrationAsIdempotent`。

### ③ 影子对账 + 人工修复入口

- 新增 `ReconciliationReport` / `ReconciliationService`（core，三存储通用）、`GlobalLockRef`、
  `GlobalLockManager#heldLocks()`（默认空，Jdbc 实现）。
- 三个入口：管理端点 `GET /_easy-at/v1/reconciliation`（boot2/boot3 均已接线）、
  独立 CLI `io.github.easyat.jdbc.ReconciliationCli`（退出码 0/2/1）、
  纯 SQL `db/{mysql,postgresql}/reconciliation.sql`。
- 新增 **`RUNBOOK.md`**：灰度 5 阶段表、告警阈值表、MANUAL_INTERVENTION / DIRTY_WRITE /
  锁泄漏的逐场景人工修复流程、每天必看清单、回滚预案。
- 回归：`ReconciliationTest` 6 例（干净环境必须 OK + 五种异常各自必须被抓到，防"对账永远健康"的假绿）。
- CLI 已在本机 MySQL `easy_at_it` 上实跑，正确报出 2 条残留 ACTIVE（退出码 2）。
