## 环境要点（发布相关，会复发）

- **Git Bash 自带的 gpg 2.4.9 是坏的**：`error running '/usr/lib/gnupg/keyboxd': probably not installed`。
  必须用 `C:\Program Files\GnuPG\bin\gpg.exe`（2.5.24）。Windows PATH 解析到 GnuPG 版
  （Git 的 `usr/bin` 不在 Windows PATH，只有 `Git\cmd`），所以 mvn 调 gpg 走的是正确版本。
- 主钥：`sec rsa3072/F8906A3147516888` [SC]，uid `amu10 <ltfcg@126.com>`。
- 沙箱三个 env 默认都是空的（`CENTRAL_TOKEN_USERNAME` / `CENTRAL_TOKEN_PASSWORD` / `GPG_PASSPHRASE`），
  每次新会话都要重新注入；settings.xml 用 `${env.*}` 引用。
- 网络：`central.sonatype.com` 200、`repo1.maven.org` 200、nexus 私服 200，发布链路可达。

## 关键坑（必看，下次发布直接复用）

1. **gpg 插件必须显式指定 executable**。Git Bash 启动时 PATH 里 `C:\Program Files\Git\usr\bin\gpg.exe`
   (2.4.9，缺 keyboxd) 排在 GnuPG 前面 → 报
   `failed to create temporary file '/c/Users/lenovo/.gnupg/.#lk...': Permission denied`
   + `can't connect to the keyboxd` + `no default secret key`。
   已在根 pom release profile 的 maven-gpg-plugin 里加
   `<executable>C:/Program Files/GnuPG/bin/gpg.exe</executable>` 解决。
   真实密钥在 `C:\Users\lenovo\AppData\Roaming\gnupg`（不是 `C:\Users\lenovo\.gnupg`）。
2. **别把明文凭证写进 Bash 命令** —— 会触发敏感内容审批并超时拦截。正确做法：写进
   `~/.m2/settings.xml`（Maven 原生位置），命令里只留 `mvn clean deploy -Prelease`。
3. Central 的旧状态 API `/api/internal/publisher/status?id=` 已 404，查状态直接去 Portal 页面。
4. GPG 口令 `Sryder!518` 已验证可用（手工 detach-sign 通过）。
